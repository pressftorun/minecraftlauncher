# Выпуск лаунчера

## Перед выпуском

1. Проверьте чистую установку, повторную проверку файлов и запуск игры на целевых платформах.
2. Обновите версию в `desktop/CreateLauncher.csproj`. Согласуйте строки версии User-Agent и запуска в `desktop/LauncherService.cs`.
3. Обновите `CHANGELOG.md` и создайте `docs/releases/v<версия>.md`.
4. Проверьте `launcher.json`: версии Minecraft/NeoForge должны совпадать с клиентским пакетом.
5. Выполните self-test и сборку по [CONTRIBUTING.md](../CONTRIBUTING.md).

## Текущее поведение CI

Push в `main` или ручной запуск workflow `Build and release` собирает Windows x64 и Linux x64, выполняет self-test и создаёт ZIP-архивы.

После успешной сборки job публикации создаёт релиз `v<версия>` с двумя архивами и `SHA256SUMS.txt`. Если релиз уже существует, публикация пропускается: для следующего выпуска нужна новая версия. Описание берётся из `docs/releases/v<версия>.md`.

Публикация происходит автоматически. Перед отправкой изменений в `main` проверьте состав diff и права доступа к репозиторию.

## Проверка результата

Скачайте опубликованный архив, сравните SHA-256 с `SHA256SUMS.txt`, распакуйте его в новую папку и проверьте запуск. В архиве не должно быть пользовательской `data/`, логов или случайно вложенного `client.zip`.

Обновите ссылки на конкретную версию в README при выпуске новой версии. При проблеме не перезаписывайте существующий релиз незаметно: опишите исправление и выпустите новую версию.
