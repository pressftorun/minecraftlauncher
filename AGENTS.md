# Предпочтения пользователя

- По умолчанию источником истины является репозиторий: списки модов, версии и состав сборки определять по его файлам. Локальные игровые установки и папку «минимум» использовать как эталон только по явному указанию пользователя для конкретной задачи.
- Для операций с GitHub сначала использовать подключённый GitHub-плагин: загрузка файлов, коммиты, ветки и публикация изменений. Не перекладывать push на пользователя из-за отсутствия авторизации в локальном Git, пока возможности плагина не проверены.
- После проверки работоспособности коммитить новые изменения в каждом затронутом репозитории. В коммит включать только изменения текущей задачи, сохраняя посторонние незакоммиченные правки.
- Не коммитить заглушки вместо запрошенной функции: в коммит должна попадать законченная и проверенная реализация.
- При каждом релизе поддерживать актуальными README, описание About, текущую версию, ссылки на скачивание и бейджи соответствующего GitHub-репозитория. Скриншоты в README и описания Releases не добавлять.
- Изменения по версиям записывать только в CHANGELOG.md. В README, RELEASE.md, docs/releases/ и описаниях GitHub Releases оставлять ссылки на CHANGELOG.md без дублирования истории изменений.
- В CHANGELOG.md должна быть отдельная запись для каждого опубликованного релиза. Недостающие записи восстанавливать по истории коммитов и содержимому релизов; не выдумывать изменения или результаты тестов.
- Перед выпуском каждого нового релиза обязательно применять навык `$pre-release-check`: проверить изменённый код и обработку ошибок, провести тесты, исправить найденные регрессии и повторить тесты. Выпускать релиз только после успешной проверки; в сводке указать найденные и исправленные баги и результаты тестов.
- При синхронизации клиентских модов сохранять оформление пакета: config/fancymenu и config/drippyloadingscreen не заменять настройками игровой установки без явного запроса пользователя.
- Эталон из папки «минимум» относится только к модам. Существующие настройки клиента (options.txt, config и оформление) сохранять, если пользователь отдельно не просит их заменить.
